Global popup

Four places the OS can put a question. The panel itself is the same in all four — the same tokens, the same button row, the same attribution line. What differs is where it is anchored, what it dims, and therefore what kind of question it can carry.

Why this exists

An app GUI runs in sandbox="allow-scripts allow-forms allow-downloads" (src/apps/host.ts:163). No allow-modals — so confirm() inside an app is already ignored by the browser. Apps cannot ask the user anything today. The shell itself still calls the browser's (DesktopShell.tsx:194, apps/hooks.ts:117), which shows the origin instead of the app, cannot be styled, blocks the whole thread, and looks like a phishing box.

One surface fixes both: the OS draws the panel, outside every iframe, and stamps who asked — the same trust move notify already makes when it stamps source from the kernel's appId.

The contract — identical across all four

One method. The app describes the question; the host decides which surface it lands on. No coordinates, no z-index, no modality flag — an app can't be trusted with those anyway. 

// app.ts
import { dialog } from '@justfiles/app/capabilities/dialog'

capabilities: { dialog }

// in a procedure — one await, and the host draws it
const answer = await app.invoke('dialog', 'ask', {
	title: 'Delete "Q3 planning"?',
	body: 'The note and its 4 revisions leave the volume.',
	confirm: 'Delete',        // omit → one OK button, informational
	destructive: true,
	input: { placeholder: 'New name', value: 'Q3 planning' }  // optional → a prompt
})
// → { ok: false } | { ok: true, value?: string }

Deliberately absent from v1: a third button, custom buttons, an icon of the app's choosing, a "don't ask again" checkbox. None has a caller yet. source is never in the payload — the host stamps it, so an app cannot ask a question in another app's name.

Reads as

AppKit's sheet. Attribution is structural — it is physically attached to the app that asked, so the label is confirmation, not the only evidence.

Best for

Anything a window owns: delete this note, save before closing, rename, overwrite.

Costs

Needs a window. A question from the agent, a cron job, or the shell itself has nowhere to hang. Behind another window it is invisible until the OS raises it.

Reuses

If it were one call

1 and 2 are one feature, not two. Same panel, same ask(); the host picks — the calling app has an open window, so it gets a sheet; the shell, agent or cron has none, so it gets an alert. That kills both browser popups in the shell, gives apps the capability, and adds one component plus one placement rule. Ship that.

3 is the second release, once the agent starts asking things mid-turn — and it wants the API change (a dismissable answer), so it is worth not paying for now. 4 is the most distinctive and the most opinionated: it makes the omnibar the single place the machine and the user meet. Choose it if that story matters more than mouse travel.
