The Crease

One fold for everything the agent does that isn't addressed to you. Thinking and tool calls today; planning, delegation and retrieval later. The crease was never really about tool calls — it's about the difference between the response and the interior.

The codebase already agrees with you — and it's already costing something

SessionEntry in packages/agent/session.manager.ts is exactly the unified stream you're describing: an ordered list of typed entries where assistant_thinking, tool_call, compaction, branch_summary and label all sit side by side. The flattening happens in sessionEntries2DisplayMessages, and three of those five kinds currently come out the other side rendered as if the agent said them out loud. Details below.
Where the line goes

Response, or interior

A design language needs one test, not a list. This one holds up for every kind that exists today and every kind I can think of adding: does it invite or require the user's attention? If yes it's the response and it renders plainly. If no it's interior and it folds. Note that this puts options and permission prompts firmly on the response side — they block — while everything the agent does on its own initiative folds away.

The language itself

Uniform shell, kind-owned content

A design language is only useful if it says what a new kind may not change. Five things are fixed for every kind, forever. Three things belong to the kind — and the third is the one that matters, because natural language and machine output should never be set the same way.

Fixed · the crease owns itWhat a new kind cannot change

  1. Chronological position — in the thread, above the response it produced.
  2. The two phases, and the settle animation between them.
  3. The seam: same hairline, same grammar, same fold.
  4. Row chrome: status dot, kind word, one line, duration.
  5. Disclosure: a row opens on click, a failure opens itself.

The status dot carries status only — running, done, failed. The kind is a lowercase word in mono. That's deliberate: at 5px, glyphs turn to mud, and a word needs no legend and no icon design for every future kind.

Kind-owned · three functionsWhat a new kind supplies

  1. A present-tense phrase for the live line — "Reading Transcript.tsx", "Thinking about the seam".
  2. A one-line rest label for its row once settled.
  3. A body, rendered however that kind's content actually wants to be read.

Implementation

What actually changes

Unifying makes TranscriptProps smaller. Two fields become one, and the one that replaces them is ordered — which is the only reason chronological placement is possible at all. Adding a kind later touches one record, not the component.
Two fields become one ordered list

thinking?: string and toolCalls?: ToolCallInfo[] are separate buckets, so nothing records that the agent thought, called a tool, then thought again. One discriminated union in message order fixes the ordering and shrinks the surface: 

// packages/ui/src/Transcript.tsx
export type Activity =
  | { id: string; kind: 'think'; text: string; status: Status }
  | { id: string; kind: 'tool'; name: string; args: unknown; result?: unknown
      isError?: boolean; images?: TranscriptImage[]; status: Status }
  | { id: string; kind: 'compact' | 'branch' | 'label'; text: string; status: Status }

export interface AgentMessage {
  /* … */
-  thinking?: string
-  toolCalls?: ToolCallInfo[]
+  activity?: Activity[]   // ordered, interleaved with content
}

Keep exporting ToolCallInfo as an alias of the 'tool' member — platform/frieren/src/agent/types.ts re-exports it and images.ts depends on the shape, so nothing outside the package has to move on day one.

The lossy step is sessionEntries2DisplayMessages

SessionEntry is already an ordered, typed, append-only stream — it is the model you're asking for, and it's upstream of the UI. The information is destroyed in the projection at platform/frieren/worker/display.ts, which sorts entries into per-message buckets: 

// display.ts — the flattening
case 'assistant_thinking':
  return { role: 'assistant', content: '', thinking: entry.content }

With an ordered activity[] the projection gets simpler, not harder: append in entry order and stop reconstructing which bucket a thing belongs in. Do this in the projection, not the component — the mac launcher's agentChat.tsx:132 does the same flattening independently and will need the same one-line change.

Three kinds are currently rendered as agent speech

This is the concrete cost of not having the category. In display.ts: 

case 'compaction':      return { role: 'assistant', content: entry.summary }
case 'branch_summary':  return { role: 'assistant', content: entry.summary }
case 'label':           return { role: 'assistant', content: `[${entry.label}]` }

A user scrolling back sees the agent apparently announce a compaction summary, or say [before refactor], in the same voice it answers questions in. These are interior events wearing the response's clothes. Three of the five kinds that exist today are mis-rendered, which is the strongest argument for fixing the category rather than special-casing thinking.

Live and replay currently disagree

Worth fixing in the same pass, because the unified list fixes it for free. During streaming, platform/frieren/src/os/client.ts:298 seeds one message with both thinking: '' and toolCalls: [] and accumulates deltas onto it. On replay, display.ts gives thinking its own message.

So the same turn renders differently live than it does after a reload. One ordered activity[], appended to in both paths, removes the divergence by construction.

A kind is three functions

The whole extension point. Adding recall or delegate later means one entry here and nothing else: 

// The crease owns position, phase, seam, row chrome, disclosure.
// A kind owns only what it says and how its body reads.
const kinds: Record<Activity['kind'], {
  live(a): string          // "Reading Transcript.tsx" — for the status line
  rest(a): string          // "Transcript.tsx"        — for the settled row
  body(a): ReactNode       // <pre> for tools, prose for thinking, a crease for delegate
}> = { /* … */ }

Never render thinking in mono. It's natural language; <pre> makes it look like a log and reads badly. Today's code already knows this — Transcript.tsx:275 passes mono={false} — which is exactly the kind-specific body rule, discovered the hard way and hardcoded in one place.

Grouping, labels, and the two switches above

Merged. One crease per contiguous run, regardless of kind. Fewer seams, and a mixed run reads as one unit of work — which is what it was. Switching to By kind in the mockup shows the cost: four seams where one would do, and the thread starts to look striped. Merged is the default.

Labels specialise when a run is homogeneous. All thinking → "Thought for 8.4s". One tool → that tool's own phrase. Mixed → "6 steps · 7.4s". Terse stays the default; the narrated variant remains a setting.

Streamed thinking. Showing the live thought fragment is the most alive the agent ever looks, and it costs nothing — the text is already streaming. But it's the one place raw model output reaches the user unmediated, so it wants a hard truncation and a setting. Quiet mode ("Thinking · 6.2s") is the safe default for a shipped app; streamed is right for your own machine.

Scroll, and one thing that gets easier

Free: during a turn the seam is the last thing in the thread, so the stick-to-bottom in Transcript.tsx:186 keeps it visible with no extra work, and settling doesn't change the node's height.

Still needed: unfolding grows content below the seam. The ResizeObserver re-pins while stuckRef.current is true, so opening an older turn yanks the view to the bottom. Set stuckRef.current = false in the toggle, before the growth lands. A nested crease makes this worse, not better — the growth can be large.

Accessibility

Running phase: role="status", aria-live="polite", aria-atomic — so each phrase is announced rather than the thread re-read. Settled: a real <button aria-expanded> with the label as its accessible name. Nested creases nest the buttons; nothing special is needed.

Under prefers-reduced-motion, drop the rotateX hinge and the rule sweep, keep plain fades. The hinge is decorative; the disclosure is not.
