T20 · revised architecture

Conflict recovery is one small decision machine.

Sync stays a loop. When the authority rejects a page, it calls one recovery subroutine. Only the policy decision inside that subroutine is a state machine.

The whole sync lifecycle

There is no new syncPage(). Existing drain() reads change-feed pages and hands each batch to push(rows) or pull(rows). Recovery is one addition to the structured conflict branch.

class Replan extends Error {}

const RECOVERIES = 4096
const recovered = new Set<string>()
let recoveries = 0

const push = async (rows: Node[]) => {
	await transfer(rows, local.blobs, remote.blobs)
	try {
		await remote.commit(rows)
	} catch (error) {
		if (!(error instanceof GuardError)) throw error
		if (!isSyncConflict(error.reason)) throw error

		const fingerprint = conflictFingerprint(error.reason, rows)
		if (recovered.has(fingerprint)) throw new RecoveryLoopError(fingerprint)
		if (recoveries === RECOVERIES) throw new RecoveryLimitError(RECOVERIES)
		recoveries++

		const outcome = await recover({
			conflict: error.reason,
			rows,
			local,
			remote,
			recovery: opts.recovery,
			replica: opts.replica,
		})
		if (outcome.kind === 'applied') {
			recovered.add(fingerprint)
			throw new Replan()
		}
		if (outcome.kind === 'raced') throw new Replan()
		throw outcome.error
	}
}

for (;;) {
	try {
		await drain(local, push, opts.push, mine)
		await drain(remote, pull, opts.pull)
		return
	} catch (error) {
		if (!(error instanceof Replan)) throw error
		continue
	}
}

The entire state machine

It receives immutable conflict facts, evaluates ordered rules, and always returns one of three decisions. The dashed boundary is intentional: copying, verification, cleanup, and retries stay outside.

Repair

Apply a known guarded change, then retry. Revival and rename live here now; a future clean three-way merge fits here too.

Preserve

Copy a known malformed local graph privately, verify it, apply server-wins locally, then retry.

Unresolved

Conservatively copy the rejected local graph privately for later triage, apply server-wins locally, then retry.

One necessary boundary

Policy fallback

unresolved catches every unknown conflict. It cannot catch a full private store, unavailable bytes, or repeated guard races without risking data loss. Those are operational failures: leave the shared source untouched and surface the sync error.

Recovery never writes private items to the remote. The existing push may already have transferred an unreachable source blob before the authority rejects its row; avoiding that requires a separate validate/reserve protocol.
