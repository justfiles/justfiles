Recover rejected sync rows

The authority wins. Preserve displaced local data privately before cleanup. If settlement would strand authority children, keep shared rows unchanged and report the error.

Keep Store and Volume unchanged. Restore affected rows in place through existing APIs; settle absent ids with guarded tombstones. T21 safely collects them after retention. Resume existing cursors; expired history still requires T21 bootstrap.

One policy decision

structured push refusal
	│
	├─ resume recorded settlement
	│
	└─ otherwise decide(facts)
		├─ M01–M03  repair       revive or rename
		├─ M04–M08  preserve     known structural conflict
		└─ M09      unresolved   unknown conflict

preserve / unresolved
	→ copy and verify privately
	→ settle absent ids at authority
	→ persist adoption receipts
	→ guard-adopt authority rows locally
	→ restart sync

The decision function is pure. Reads, copying, guards, receipts, and retries belong to the executor.

Four safety rules

RiskRule
Restored rows overwrite newer server editsPersist exact-version adoption receipts before local installation. Every push skips receipted versions; fresh edits still push.
An absent parent already has server childrenCheck children inside the authority's serialized commit path. Refuse unsafe settlement without changing either replica.
The refusal omits selected descendantsOmission means unknown. Read every selected authority id; guard absent ids and never push adopted rows back.
Recovery consumes ordinary replan limitsUse a separate restart signal and a 4,096-attempt recovery budget. Keep ordinary pull replans bounded.

Receipts survive crashes and cursor resets. Verify recovered copies again before resuming cleanup. A changed source requires recapture, including new descendants.
