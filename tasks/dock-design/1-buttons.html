Diagnosis

It isn't only the gloss

The gloss is what your eye caught, but the real tell is that no app actually uses the platform button. Every app that needs more than "a box that says Cancel" reaches past mac.css and hand-rolls its own — and they all reach for the same missing things.

A

Sequoia Flat

The geometry was never the problem — the lighting was. Delete the gradient, the inset highlight and the text-shadow; keep everything else and let the tokens do the work. This is what a Mac control has looked like since Big Sur, and it is what every app in the repo already hand-rolls when it wants a primary button.

Why it fits

Cheapest possible move. One rule block shrinks, nothing else in the system shifts.

It stops the button from shouting, so the glass shell reads as the loudest thing on screen — which it should be.

Where it hurts

It removes a mismatch rather than answering one. On the wallpaper, a flat white button still sits on the glass like a decal.

Quiet to the point of plain. There is no idea here, only good hygiene.

The delta

/* mac.css — primary */
- background: linear-gradient(…)
- box-shadow: inset 0 1px 0 …
- text-shadow: 0 1px 0 …
+ background: var(--accent);

/* plain */
  border-radius: 6px;   /* was 5 */
  padding: 4px 12px;   /* was 2px 11px */
+ box-shadow: 0 1px 1px rgb(0 0 0/.04);
+ :focus-visible → the input ring
B

Glass Control

The shell already has a material; the controls just aren't made of it. The dock defines five glass tokens — tint, sheen, rim, bounce, edge — and keeps them locked inside app.css. Promote them into design.css and cut buttons from the same sheet, so a control on the desktop and a control in a window are visibly one system.

Why it fits

Total cohesion. Look at the wallpaper strip: the button and the omnibar are the same object.

It is the only direction that makes floating chrome — sheets, HUDs, the agent panel — feel designed rather than assembled.

Where it hurts

Glass over an opaque window is just a tint. Compare the two rows above: the material only pays for itself where something is behind it.

Contrast is the real risk, and backdrop-filter on every button is not free.

The delta

/* design.css — hoist from app.css */
+ --glass-tint / --glass-sheen
+ --glass-rim  / --glass-bounce
+ --glass-edge

/* mac.css */
  background: linear-gradient(180deg,
    var(--glass-sheen), transparent 34%),
    var(--btn-glass);
  backdrop-filter: blur(14px) saturate(180%);
  border-radius: 9px;
C

Keycap

What Aqua got right was that it looked pressable. Keep that and throw away the gloss: a flat fill plus one solid edge underneath, and a press that drops 1.5px and eats the edge. The affordance survives; the decade doesn't. It is the only direction where clicking feels like anything.

Why it fits

Answers the shell's own brief. The omnibar doc insists a teenager or a sixty-year-old should see what to do without being told — this is the most obvious button on the page.

Its edge is one flat colour, so it stays honest in dark mode where gradients go muddy.

Where it hurts

It has a personality, and that personality is toy-ish. In a dense Settings pane, twelve keycaps in a column is a lot.

The 1.5px drop is real motion; it needs a reduced-motion guard and care next to tight layout.

The delta

/* mac.css — plain + primary */
  box-shadow: 0 1.5px 0 var(--keycap-edge);
  border-radius: 7px;
  transition: transform 70ms ease;

  :active {
    transform: translateY(1.5px);
    box-shadow: 0 0 0 var(--keycap-edge);
  }

+ --keycap-edge  /* one new token */
D

Hairline

A desktop is already busy; controls should get out of the way. Kill the fill entirely. A button becomes a label inside a hairline, and only the Return-key action gets colour. The shell is already doing this behind the platform's back — its own toggles are a transparent box with a 7% ink wash on hover.

Why it fits

It is what the shell already built. Adopting it makes design.css describe reality instead of contradicting it.

Leanest CSS of the five, and the primary button becomes genuinely the only coloured thing in a window — which is the point of a default action.

Where it hurts

It bets against discoverability — the shared principle the omnibar doc is built on. A hairline is a designer's button.

On the wallpaper it nearly vanishes; toolbars of these read as a row of text.

The delta

/* mac.css — plain */
  background: transparent;
  border: 1px solid
    color-mix(in srgb, var(--text) 17%, transparent);
  :hover { background:
    color-mix(in srgb, var(--text) 7%, transparent); }

/* --control-bg / -hover / -active become
   input-only tokens */
E

Two-Actor

A classic OS assumes one actor. Frieren has two. If the agent dispatches the same actions the human clicks, a control should say so: a blue dot marks an action the agent can also take, and while the agent is taking it the button holds the same glow the omnibar pill uses when it is working. Surface treatment borrowed from A; the idea is the vocabulary.

Why it fits

It comes straight out of the design docs. "Two actors, one workspace" and "the GUI is a live projection of reducer state" — co-presence is currently invisible in the controls.

It also finally uses --danger, and gives apps the ghost/small/link variants they keep re-inventing.

Where it hurts

It is the biggest interface expansion — and the house rule is to be very stingy with interfaces. Five new attributes is a real cost.

The busy state duplicates presence the pill already shows. Worth building only if per-control presence is genuinely wanted.

The delta

/* A's surface, plus a vocabulary */
  [data-primary]           /* exists */
+ [data-danger]            /* uses --danger */
+ [data-ghost]
+ [data-size="sm"]
+ [data-actor="agent"]     /* agent can too */
+ [data-busy]              /* agent is now */

   busy = --focus ring + travelling sheen,
   matching the pill's working glow

If it were mine

Ship A, then add E's vocabulary. A is a deletion, not a redesign — it costs one rule block and immediately stops the button fighting the shell. Then the variants from E (danger, ghost, sm) pay for themselves the moment apps/code and apps/settings delete their hand-rolled copies. Hold actor and busy until per-control presence is actually wanted.

B is the one to pick if cohesion is the real goal — it is the only direction that makes the window and the desktop look like one machine, and the only one with a genuine technical risk to weigh.
