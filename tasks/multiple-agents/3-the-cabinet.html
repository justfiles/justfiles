Two layers,
not three.

You are right, and it is my bug. I gave the rail its own edge, its own groove and its own cast — a second complete seam — so it reads as sunk below the drawer, which is sunk below the desktop. Three planes. The fix is to stop treating them as two objects.

what you're seeing

Two seams make three planes

A seam is an expensive mark: an edge, a groove and a cast together say this surface has been cut, and what's behind it is deeper. I spent that mark twice. Here is the screen in cross-section, looking at it edge-on.

the rule

One slot, one seam, one slab. The desktop is cut; everything behind the cut is the same piece of material. A boundary inside that material is a scored line — one hairline, no groove, no cast, no second background.

This also settles a question the three-plane version left open: what is the rail for? Sunk below the drawer, it looked like a separate mechanism. Flush with it, it is obviously what it should be — the front of the cabinet, with the drawer pulled out beside it.

the revision

The same shell, one mark cheaper

Toggle the material to see the plane appear and disappear. Nothing else changes — same layout, same travel, same caps.

what falls out of the rule

Four details the one-slab model decides for you

  • 01The divider disappears when the drawer is shutWith nothing pulled out, the hairline would sit a pixel from the seam and read as a doubled edge. So it fades out on close and back in on open — it exists to divide two regions, and when there is only one region there is nothing to divide.
  • 02The lip runs across bothThe top-and-bottom shading that makes the drawer sit in a slot now belongs to the cabinet, not the drawer. Shading only half the slab was the other thing splitting it in two.
  • 03The pressed cap is the only thing allowed to break the lineA cap whose drawer is out squares its left corners and slides over the hairline. That is the connective mark — this cap opens into this drawer — and it earns its place precisely because nothing else interrupts the line.
  • 04One background, not two#25232f and #26242e were close enough to look like a mistake and far enough apart to read as two objects. One slab, one value, derived from --surface exactly as the panel already does.

the change

The shell goes back to two children

Which is the part I like most: the fix makes the tree shallower, not deeper. The cabinet is the flex sibling that used to be the chat panel; the panel and the rail move inside it and stop owning any material. 

/* .frn-shell — two children, two planes */
.frn-shell            display:flex
├─ .frn-desktop-frame flex:1      — menubar + desktop, squishes
└─ .frn-cabinet       flex:none   — paints the seam and the lip, once
   ├─ .frn-chat-panel 0 → width   — travels; no material of its own
   └─ .frn-agent-rail 64px        — a hairline, nothing else

/* the cabinet takes what the panel used to paint */
.frn-cabinet {
  display: flex;
  height: 100vh;
  z-index: 9001;
  background: light-dark(
    color-mix(in srgb, var(--surface) 90%, black),
    color-mix(in srgb, var(--surface) 84%, black));
  box-shadow:
    inset 1px 0 0 var(--seam-edge),      /* the cut face   */
    inset 2px 0 0 var(--seam-groove),    /* behind it      */
    inset 12px 0 18px -10px var(--seam-cast),
    inset 0 16px 20px -16px var(--drawer-lip),
    inset 0 -16px 20px -16px var(--drawer-lip);
}

.frn-chat-panel {
  flex: 0 0 auto;
  transition: width 460ms var(--drawer-ease);
  background: …;  ← moved to .frn-cabinet
  box-shadow: …;  ← moved to .frn-cabinet
}

.frn-agent-rail {
  flex: 0 0 var(--rail-w);
  border-left: 1px solid var(--cabinet-score);
  transition: border-left-color 300ms ease 120ms;
}
/* nothing to divide from when the drawer is in */
.frn-cabinet[data-open="false"] .frn-agent-rail {
  border-left-color: transparent;
  transition-delay: 0ms;
}

One new token

--cabinet-score: light-dark(rgb(0 0 0 / .11), rgb(255 255 255 / .11)) — a scored line, deliberately not --rule. It sits on the sunk slab, not on window chrome, and it must stay quieter than the seam it lives behind.

What the resizer does

Nothing changes. The grab handle stays at the drawer's left edge, on the seam, where .frn-chat-resizer already puts it. The hairline between drawer and rail is a mark, not a splitter — the rail is a fixed width and there is nothing there to drag.

Mockup is stylized — UI drawn oversized to read at this scale. The seam recipe, the token names and the 460ms travel are from src/app.css; the tree is src/shell/DesktopShell.tsx.
